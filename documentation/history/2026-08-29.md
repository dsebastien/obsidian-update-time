Two commits from the fleet-review pass (obsidian-plugin-template is the canonical source):

2. **Declarative settings port (feat!, minAppVersion 1.8.7 → 1.13.0)**: `getSettingDefinitions()` replaces the `display()` tab. The two property names and the save delay are plain controls; the excluded-folder list is a native `type: 'list'` (top level — a group's `items` cannot host one) with an inline folder-autocomplete add row, since the framework's `addItem` affordance hands back a bare element and the completion is the point.

    The write path is a serialized persist-then-commit `updateSettings(mutator)` shared by the tab and the post-migration save in `loadSettings` (a fire-and-forget save could otherwise finish after a user edit and restore the pre-edit state). The debouncers every timestamp write goes through are reset strictly after a successful commit, so a failed write can no longer make a changed save delay look applied.

    Behavior change, deliberate: an invalid save delay is now refused with an inline error instead of being silently replaced by the default, which used to hide typos. Deleting a folder resolves the entry by value before the write, so two deletions from the same render remove exactly those two entries.
